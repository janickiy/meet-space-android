# Этап 02: план и выявленные пробелы

Дата: 2026-10-11. Основание: запрос пользователя и CODEX_ANDROID_02_02_ANDROID_FOUNDATION.md. Аудит этапа 01 сохранён рядом; этот этап не включает звонки, чаты, SSH-развёртывание или изменение backend.

## План до реализации

1. Создать Kotlin/Compose/Material 3 проект: app, core:model, core:data, core:designsystem. Использовать текущую первую версию дизайна из go-recorder/design/meetspace-android-20261010.
2. Сделать первый запуск, ввод HTTPS-сервера, проверку публичного /version, вход, /auth/me и защищённый /capabilities. Последовательность capabilities после входа обусловлена фактической авторизацией backend.
3. Изолировать серверы и аккаунты. Настройки и список профилей в DataStore; access token только в памяти; durable session cookie в AES-GCM хранилище с ключом Android Keystore. Пароль не сохранять. Восстанавливать вход через refresh. При выходе удалять локальный секрет, включая ошибку сети.
4. Реализовать адаптивную навигацию: нижнее меню, rail, постоянный drawer; четыре вкладки; системная/светлая/тёмная тема; прокрутка и доступность. Функции следующих этапов обозначить как ещё недоступные.
5. Проверить unit/Compose тестами URL, профили, refresh/logout, onboarding, изменение размера и rotation. Собрать APK и запустить на ARM64 планшетном эмуляторе; отдельно проверить реальный вход с предоставленным пользователем тестовым аккаунтом. Секреты только во временном приватном файле, вне проекта и отчёта.

## Пробелы и решения

- В среде нет JDK и Android SDK. Установить локальные инструменты и эмулятор, зафиксировать версии и контрольную сумму Gradle Wrapper.
- Production /version отличается от checkout backend. Не утверждать совместимость по SHA: проверить реальный протокол /version, login, me, capabilities и refresh; показать версию пользователю.
- /capabilities требует Bearer: запросить после входа. /health скрыт proxy: не использовать его как критерий доступности.
- Backend возвращает durable session как HttpOnly Secure cookie, а не refreshToken JSON. Использовать фактический cookie протокол, без браузерного Origin.
- В mobile_maket нет файлов; доступен актуальный handoff в локальном backend checkout. Переиспользовать его токены и композицию нативными средствами.
- Развёртывание через SSH не реализуется в этом этапе: пункт первого запуска открывает информационный экран; не имитировать успех установки.
