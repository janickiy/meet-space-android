## Выводы аудита и пробелы

- Записи: GET `/conferences/{cid}/recordings` с limit/offset, detail GET `/conferences/{cid}/recordings/{rid}`. Detail повторно проверяет доступ и выдаёт signed URLs хранилища. Показываем только готовые записи с доступным final_mp4/final_audio. Legacy routes не используем.
- Общей коллекции записей нет. Вход через список доступных встреч и историю; встреча задаёт область записей и материалов. Пагинация обязана сохранять доступ к остальной истории.
- Расшифровки, сегменты и итоги существуют в API, но зависят от возможностей сервера. Недоступность/отсутствие материалов показывается честно; обработку записи и ИИ не запускаем автоматически.
- Профиль, история, тема, серверы, выход и настройки уведомлений уже реализованы. Объединяем доступ к настройкам, добавляем сведения о приложении/данных и системные разрешения. Не создаём несуществующие серверные настройки.
- Дизайн: существующий shortcut «Записи» во встречах, карточки записи, player/download и переход из истории. Новая шестая вкладка не нужна. Технические ready/processing/failed не выводим.
- Firebase и push-шлюз пока не настроены (уточнение пользователя на этапе 07). Фоновые push останутся выключены; текущий центр уведомлений работает.
- Релизного keystore нет в доступной конфигурации. Подготовим debug APK, unsigned release APK/AAB и безопасную optional signing-конфигурацию без секретов в исходниках. Публикация не входит в этап.
- Native WebRTC/AndroidX требуют проверки ZIP/ELF 16 KiB и по возможности запуска на соответствующем эмуляторе. Статическая проверка сама по себе не доказывает runtime-совместимость.

## Реализация

1. Модели/repository записей и материалов с проверкой идентификаторов и авторизации. Потоковый transport без auth/cookie на signed storage URL, без redirect/TLS bypass, поддержка Range, отмена и очистка при смене аккаунта.
2. Экран записей и материалов, native Media3 player, SAF export без широкого доступа к хранилищу; прогресс, отмена, очистка частичного документа. Ссылка получается заново через авторизованный API, в UI/логи не попадает.
3. Входы из «Встречи»/истории; настройки уведомлений, тема, privacy/about/permissions. Адаптивность, light/dark, доступные названия/фокус, rotation/multiwindow.
4. Изолированная fixture настоящего backend с тестовыми готовыми медиа, проверка доступа/пагинации/скачивания. Это проверяет потребление готовых записей, но не заменяет тест полной записи Pion/worker.
5. JVM/UI/live проверки, smoke существующего сервера и SSH onboarding (честные ошибки без DNS/доступа), сборка APK/AAB, проверка manifest/signing/секретов/нативных библиотек.
6. Privacy/data flow, permissions review, signing/config guidance, release checklist и итоговый отчёт с фактическими результатами, ограничениями и файлами.

## Границы

Не меняем backend production, не публикуем приложение, не создаём постоянный ключ подписи без решения владельца, не заявляем проверенными физические устройства/FCM/полную запись без выполненного теста. После этого этапа останавливаемся.
