# Этап 05 — главная, встречи, календарь и личный кабинет

Дата: 11.10.2026. Область определяется прямым запросом пользователя. Приложенный `CODEX_ANDROID_07_07_MESSAGING_FOLDERS.md` описывает другой этап; чаты, папки, файлы и push в эту реализацию не входят. Файл этапа 05 из той же папки прочитан как справочный материал.

## Фактическая исходная точка

- Android 0.4.0: авторизация, профили HTTPS-серверов, адаптивная навигация, SSH и Docker-установщик. Главная и звонки пока содержат заглушки; профиль показывает аккаунт, сервер и настройки темы.
- Контракты сверяются с чистым checkout backend `6ecd8b648a2aa94fc9bcc844d57784423e2c6f69` в `.audit/meet-space-stage04`, включая REST handlers, domain DTO и frontend. Рабочий backend пользователя не изменяется.
- Дизайн первой версии: `go-recorder/design/meetspace-android-20261010`. Существующие цвета, формы, типографика и адаптивные пороги сохраняются.
- Подтверждены `/me/conferences` с тремя видами и cursor pagination, создание/расписание/жизненный цикл, приглашения и членство, история и `PATCH /auth/me` для displayName.

## План

1. Зафиксировать точные DTO, фильтры, права и gaps в `05_API_CONTRACT.md`.
2. Добавить модели и REST adapter в существующий защищённый auth context: HTTPS, точный origin, отменяемые запросы, ограничение ответа, curated errors; токен не передаётся UI.
3. Главная показывает фактические ближайшие и активные встречи; список — будущие/активные/история, scope и дозагрузка. Создание, планирование, переходы и вход принимаются только после ответа сервера.
4. Календарь получает все три вида в границах месяца для выбранного часового пояса, поддерживает выбор дня и дозагрузку. Сохраняется `Instant`; локальные даты не принимаются за UTC. Неоднозначное/несуществующее время DST обрабатывается явно.
5. Личный кабинет редактирует поддерживаемое имя, показывает аккаунт, сервер, тему, возможности и управление сессией.
6. Проверить API wire contracts, auth isolation/expiry/cancellation, отсутствие повторного POST при неопределённом исходе, календарные границы, UI phone/tablet portrait/landscape и font scaling. Собрать debug и minified release, выполнить lint, записать фактические результаты.

## Известные gaps и ограничения до реализации

- Capabilities не содержат флагов meetings/calendar/profile. Нельзя выдумывать их: 404/405/410 фиксируются как отсутствие API, разрешения проверяет сервер.
- Нет отдельного dashboard/count/calendar endpoint: главная и календарь используют серверный timeline, без фиктивных счётчиков.
- Профиль поддерживает только displayName. Изменение email, пароля, аватара и аккаунт push registration не подтверждены.
- У создания встречи нет idempotency key: после сетевой неопределённости сначала перечитывается список; автоматическое повторение мутации запрещено.
- Вход/допуск в встречу не означает подключение аудио/видео: WebRTC относится к отдельному этапу. Этот экран честно показывает членство и допуск.
- Production допускается только для согласованной авторизации и чтения. Изменения встреч для проверки выполняются на временном staging, если доступен, либо отмечаются как не проверенные на реальном сервере.
- Данные встреч/истории остаются в памяти и очищаются при смене origin/аккаунта, выходе или истечении сессии. Постоянный offline cache этим этапом не вводится.

Работа останавливается после указанного этапа; публикация и следующий этап не запускаются автоматически.
