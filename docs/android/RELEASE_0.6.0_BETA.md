# MeetSpace Android 0.6.0-beta

Версия приложения: `0.6.0-beta`, Android versionCode: `43`.

## Исправление в сборке 43

Поле «Домен будущего MeetSpace» принимает домен или HTTPS-адрес, например `https://chat.stage.org.ru/`. Перед проверкой сервера адрес преобразуется в `chat.stage.org.ru` и отображается в поле. Регистр и международные домены обрабатываются единообразно во всём мастере.

Эквивалентный HTTPS-адрес сохраняет привязку к уже проверенному SSH-доступу и не вызывает повторный ввод пароля. Путь, порт, параметры, фрагмент и учётные данные в адресе по-прежнему отклоняются; поле SSH-хоста URL не принимает.

APK подписан прежним ключом beta-сборок. Подписанные сценарии серверного установщика и нативные библиотеки в этой сборке не менялись.

## Установщик

- Новый состав серверных контейнеров: `record-worker` вместо `worker`, без удалённого `live-worker`; proxy собирается вместе с административной панелью.
- По умолчанию используется сборка актуальной основной ветки GitHub. План фиксирует полную версию, commit, SHA-256 архива и входных файлов; запуск и продолжение используют этот снимок без повторного выбора версии.
- В мастере доступны включение админки, логин и отдельный HTTPS-порт (по умолчанию `8081`). Пароль с подтверждением задаётся непосредственно перед установкой. Он не сохраняется в Android DataStore, SavedState, плане или журнале событий.
- Сервер получает пароль по SSH/stdin и временно хранит его в файле root с правами `0600`. После подтверждённого создания администратора файл удаляется. Повторный запуск сверяет существующий аккаунт и не сбрасывает пароль.
- После установки показаны адрес админки и действия открытия/копирования. LDAP / Active Directory подключается в её настройках; сам LDAP-сервер установщик не разворачивает. Ключ шифрования параметров каталога сохраняется при продолжении установки.
- Проверяется отдельный HTTPS-вход, необходимость авторизации и запрет административного API на публичном порту `443`. Внутренний порт API `8082` не публикуется.
- Режим готовых образов сохранён, включая теги с префиксом `v` и без него. Принимаются только опубликованные совместимые пакеты с проверенными архивами, архитектурой, происхождением образов и отчётами безопасности. На момент проверки GitHub возвращает `PREBUILT_UNAVAILABLE`; автоматического переключения режима нет.
- Для сохранённых заданий 0.5.2-beta включён исходный подписанный bundle. Он выбирается по проверенной подписи и точному хешу рецепта, только для восстановления прежнего задания. Это не автоматическое обновление уже установленного бэкенда.

## Совместимость бэкенда

Проверенный снимок: [`a8274df8e29be96fd13083202e9adaebe9c5f9b1`](https://github.com/janickiy/meet-space/commit/a8274df8e29be96fd13083202e9adaebe9c5f9b1), версия источников `0.6.1-source.a8274df8e29b`.

Он включает единый вход по email/паролю для LDAP. В опубликованном теге бэкенда `0.6.1` этого контракта ещё нет, поэтому для новой установки выбран актуальный commit основной ветки.

Во время проверки обнаружен блокер commit `495ef34`: были удалены исторические SQL-файлы, обязательные для мигратора. Исправление `a8274df` восстанавливает их без изменения содержимого и опубликовано отдельно в репозитории бэкенда. Подписанный рецепт Android теперь проверяет наличие всех 49 исторических миграций до изменения сервера.
