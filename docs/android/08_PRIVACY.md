# Этап 08 — данные, конфиденциальность и разрешения

Дата ревью: 2026-10-11. Приложение: `com.meetspace.app`, 0.8.0 (7). Это технический документ для владельца продукта и выпуска; он не является опубликованной политикой конфиденциальности. Результаты выполненных проверок фиксируются отдельно в отчёте этапа.

## Потоки данных

| Данные | Куда передаются | Что остаётся на Android |
| --- | --- | --- |
| Адрес пространства, email, отображаемое имя | Выбранный пользователем HTTPS backend | Профили серверов, выбранный профиль и тема в приватном DataStore; пароль не сохраняется |
| Учётные данные входа и сеанс | HTTPS API только выбранного origin; авторизация привязана к origin и аккаунту | Access token в памяти; долгоживущий credential зашифрован AES-GCM ключом Android Keystore в `noBackupFilesDir` |
| Встречи, участники, история, чаты, папки, уведомления | Авторизованные REST/WSS выбранного пространства | Загруженные данные в памяти; сообщения и signed URLs не записываются в SavedState/Bundle |
| Аудио, камера, показ экрана | Signaling выбранного пространства и медиаинфраструктура, выданная сервером (Pion/SFU, ICE/TURN) | Временные буферы медиа; приложение не обещает сквозного шифрования от участников до участников |
| Метаданные записей, расшифровка, итоги | Авторизованные endpoints выбранной встречи/записи | Память текущего аккаунта и маршрута; создание расшифровки или итогов автоматически не запускается |
| Содержимое записи | HTTPS object storage по ссылке, которую выдал авторизованный detail API | Поток в проигрыватель либо в новый документ, выбранный через системный диалог; полного видеофайла в RAM или постоянного видеокеша приложения нет |
| Вложения чата | Авторизованный API либо проверенная HTTPS signed URL согласно фактическому контракту | Временные ограниченные буферы; экспорт только в выбранный пользователем документ |
| SSH hostname/port/user, credentials, ключ сервера | Указанный пользователем VPS по SSH после проверки host key | Публичные host keys и публичный ticket установки в приватном DataStore; пароль/импортированный приватный ключ не сохраняются приложением |
| Push при отдельном включении в настроенной сборке | Firebase/FCM, backend регистрации устройства и настроенный владельцем push-шлюз | Привязка устройства/consent к origin и account, идентификаторы доставленных уведомлений; SDK управляет своим токеном. WorkManager хранит scope и идентификаторы для повторной авторизованной синхронизации, без текста сообщения |
| Экспортированный пользователем файл | Выбранный Android DocumentsProvider, включая облачного провайдера, если пользователь выбрал его | Документ принадлежит выбранному месту сохранения и остаётся после выхода; пользователь удаляет его файловым менеджером |

URL хранилища может принадлежать отдельному домену оператора. Клиент не пересылает туда bearer token/cookies backend, запрещает redirects и проверяет обычную TLS-цепочку и hostname. Ссылка хранится внутри scoped access, не выводится в UI, не копируется и не передаётся в Media3 как URL: проигрыватель использует непрозрачный локальный идентификатор. При повторном открытии доступ запрашивается заново. Выход/смена аккаунта закрывают потоки и отменяют связанные запросы.

В проверенной версии backend срок signed URL записи составляет 24 часа. Закрытие доступа на Android прекращает локальные запросы, но не отзывает уже выданную ссылку в object storage до истечения её срока. Новое открытие или скачивание снова требует авторизации через API.

Скачивание выполняется потоком: проверяются MIME-тип и известный размер, а SHA-256 — когда backend сообщает checksum. При ошибке или отмене приложение пытается удалить созданный частичный документ. Удаление зависит от DocumentsProvider и доступности его хранилища; этот случай следует проверять для поддерживаемых провайдеров. Успешный экспорт не удаляется при выходе.

`allowBackup=false`; правила Android cloud backup и device transfer исключают приватные root/file/database/sharedpref/external и device-protected домены. Это не управляет файлами, которые пользователь явно экспортировал в другое приложение/облако.

## Уведомления и внешние SDK

Firebase-проект и push-шлюз ещё не предоставлены. В текущей конфигурации отсутствует `app/google-services.json`, `FCM_CONFIGURED=false`, собственный FCM service выключен. Автоинициализация messaging, notification delegation, analytics collection и BigQuery delivery metrics выключены manifest metadata. SDK fallback `FirebaseMessagingService` удалён из merged manifest, чтобы сообщение не отображалось в обход проверки аккаунта.

SDK Firebase Messaging и WorkManager присутствуют в зависимостях. Это не доказывает работающую фоновую доставку. После добавления конфигурации потребуются согласие пользователя, разрешение Android, backend capability, регистрация текущего аккаунта, отдельные проверки token rotation/выхода/смены сервера/холодного старта. См. [настройку FCM](07_FCM_SETUP.md).

Системные уведомления приложения содержат общий текст, без содержимого переписки. Нажатие открывает центр уведомлений; актуальные данные и права проверяются через API. MeetSpace использует также OkHttp, JSch, AndroidX и native WebRTC; состав конкретного APK проверяется при выпуске. Отдельный analytics/crash-reporting SDK приложением не подключён.

## Разрешения Android

Источник: основной manifest и объединённый manifest, прочитанный из текущего `app/build/outputs/apk/release/app-release-unsigned.apk` версии 0.8.0 (7). Разрешения и компоненты ниже сверены с этим release APK 2026-10-11; после изменения зависимостей или конфигурации нужна повторная проверка финального пакета.

| Разрешение / группа | Назначение и момент использования |
| --- | --- |
| `INTERNET`, `ACCESS_NETWORK_STATE` | HTTPS REST/WSS, SSH, медиа, поток записи; наблюдение за подключением |
| `CAMERA` | Камера в видеозвонке; runtime запрос перед использованием; отказ не должен блокировать просмотр записей |
| `RECORD_AUDIO` | Микрофон звонка; runtime запрос перед использованием; просмотр записи не требует микрофона |
| `MODIFY_AUDIO_SETTINGS` | Выбор/настройка аудиовыхода звонка и воспроизведения |
| `BLUETOOTH` до API 30, `BLUETOOTH_CONNECT` | Аудиоустройства звонка; современное разрешение запрашивается для Bluetooth route. Геолокация и Bluetooth scanning приложением не запрашиваются |
| `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_MEDIA_PROJECTION` | Видимая служба при демонстрации экрана. Android MediaProjection каждый раз запрашивает отдельное согласие |
| `POST_NOTIFICATIONS` | Системные уведомления на современных Android; отказ не блокирует внутренний центр уведомлений |
| `WAKE_LOCK`, `RECEIVE_BOOT_COMPLETED` | Транзитивные Firebase/WorkManager компоненты доставки/запланированной синхронизации; не означают разрешение постоянно записывать камеру/микрофон |
| `com.google.android.c2dm.permission.RECEIVE` | Транзитивный FCM transport |
| `com.meetspace.app.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` | Signature permission AndroidX для защищённых динамических receivers |

Нет `MANAGE_EXTERNAL_STORAGE`, `READ_EXTERNAL_STORAGE`, `WRITE_EXTERNAL_STORAGE`, `READ_MEDIA_*`, contacts/location permissions. SAF предоставляет доступ только к выбранному файлу/документу; приложение не запрашивает доступ ко всему хранилищу. Камера и микрофон в `<uses-feature>` необязательны.

В профиле экран «Разрешения устройства» показывает текущее состояние камеры/микрофона/уведомлений и открывает системную страницу приложения. После возврата состояние читается снова. Собственные services не экспортированы; launcher Activity экспортирована для обычного запуска. Транзитивные exported receivers/services отдельно проверяются по merged manifest и их signature permissions, а не объявляются отсутствующими.

## Что должен определить владелец перед публикацией

- Оператор пространства и контакты поддержки/удаления аккаунта, сообщения и записей; фактические сроки хранения, регионы хранения и резервные копии backend/object storage.
- Какие сервисы транскрипции/ИИ/TURN/object storage реально включены на сервере и каким поставщикам отправляются данные. Android capabilities не заменяют этот перечень.
- Пользовательское уведомление о записи встречи и правила доступа к записи, экспорту, материалам и участникам.
- Публичная политика конфиденциальности, согласованные тексты магазина и сведения о безопасности данных для фактически распространяемой конфигурации, включая FCM, если его включат.
- Проверки отзыва разрешений, завершения показа экрана, выхода/смены аккаунта, отзыва server access и отказов document provider. Результаты в отчёте, а не предположение на основании кода.
