## Реализовано

- Во «Встречах» и истории работает переход к записям. Сначала выбирается доступная встреча: общего API записей на backend нет. История, записи и расшифровка загружаются страницами; поиск явно относится к загруженным встречам. Технические статусы обработки и диагностические файлы скрыты.
- Нативный Media3 проигрыватель воспроизводит MP4/M4A через настоящий HTTPS transport. Поддержаны перемотка, пауза, сохранение позиции и паузы при повороте. В фоне воспроизведение приостанавливается; закрытие экрана освобождает проигрыватель и доступ к файлу.
- Сохранение через Android «Создать документ» передаёт файл потоком, проверяет размер и SHA-256. Широкие разрешения на накопитель не нужны. Есть прогресс и отмена; частичный документ удаляется при ошибке/отмене, а отказ провайдера удалить его сообщается пользователю. Успешный экспорт остаётся в выбранном месте.
- Signed URL запрашивается заново через авторизованный detail API и остаётся внутри доступа, привязанного к аккаунту. В UI, Media3 URL, SavedState и журнал его не передаём. Хранилище не получает bearer/cookies backend; redirects запрещены, TLS/hostname verification включены. Выход и смена профиля закрывают запросы и потоки.
- Расшифровки и итоги читаются из фактического API. Готовые исторические материалы доступны и при выключенной генерации новых материалов. Вкладки расшифровки/итогов остаются доступны при длинном тексте. Ошибка отзыва доступа очищает приватные данные и показывает понятное сообщение.
- В профиле объединены тема, центр уведомлений, текущие разрешения, переход в системные настройки, версия и сведения об обработке данных. Разрешения обновляются при возврате из Android Settings. Запрос открытия центра уведомлений закрывает запись/проигрыватель и обрабатывается один раз.
- Широкое окно показывает список и карточку рядом, узкое окно или большой шрифт — последовательно. Проверены светлая/тёмная темы, крупный шрифт, поворот, изменение доступной ширины, доступность кнопок, подписи и активация клавишей Enter.
- Подготовлены debug APK, minified unsigned release APK, unsigned AAB, R8 mapping и optional signing через четыре переменные окружения. DataStore обновлён до 1.2.1 после проверки нативных библиотек; Media3 закреплён на 1.11.1.

## Ограничения и следующий выпуск

1. Проверялось **чтение готовой записи** настоящего backend и приватного MinIO. Готовые тестовые H.264/AAC файлы созданы FFmpeg, исторические материалы явно подготовлены для стенда. Полный Pion → worker → запись → STT → AI pipeline и внешние провайдеры в этом этапе не проверялись.
2. Backend выдаёт storage URL со сроком до 24 часов. После исключения участника новый API-доступ запрещается, но ранее выданная ссылка действует до истечения срока. Android закрывает собственные потоки при выходе/смене аккаунта; мгновенный отзыв уже выданной storage capability требует серверного изменения.
3. Firebase и push-шлюз пока не настроены. Фоновая доставка выключена; центр уведомлений работает. После настройки владельцем нужны отдельные live push проверки по [07_FCM_SETUP.md](07_FCM_SETUP.md).
4. SSH onboarding проверяет настоящую ошибку соединения с закрытым локальным портом и показывает инструкцию. Новый VPS не разворачивался: для полного smoke нужны отдельный разрешённый сервер, DNS и SSH-доступ. Успешная установка не имитировалась.
5. Проверки 16 КиБ относятся к ARM64 эмулятору API 36 с отключённой совместимостью. Они не заменяют физические устройства, x86_64, все нативные операции, OEM/battery сценарии и доставку Play splits. Формальные замечания GNU_RELRO в graphics-path и x86_64 WebRTC сохранены в отчёте; их нельзя выдавать за доказанный crash или за полную совместимость всех ABI.
6. Автотесты проверили semantics, фокус, размеры кнопок и изменение ширины. Ручной проход TalkBack, аппаратная клавиатура, настоящий режим разделённого экрана и полный парк планшетов 7–13″ остаются проверками выпуска. Многогигабайтные записи, нехватка места и все облачные DocumentsProvider физически не проверялись; ограничение объёма потока, ошибки, checksum и отмена покрыты автоматическими тестами.
7. Перед распространением владелец подключает постоянную подпись, проверяет обновление приложения, задаёт реальные сведения об операторе/хранении/удалении и публикует политику. [Документ потоков данных и разрешений](08_PRIVACY.md) является технической основой, а не опубликованной политикой.
