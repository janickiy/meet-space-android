# Этап 05 — главная, встречи, календарь и личный кабинет

Завершён 11.10.2026. Android **0.5.0**, versionCode **4**. Реализован прямой запрос пользователя. Приложение `CODEX_ANDROID_07_07_MESSAGING_FOLDERS.md` относится к чатам; этот этап не выполнялся. План перед кодом: [05_MEETINGS_PLAN.md](05_MEETINGS_PLAN.md).

## Реализовано

- Четыре раздела: главная, встречи, календарь, профиль. Сохранены дизайн первой версии, системная/светлая/тёмная темы, bottom navigation / rail / drawer. Детали встреч открываются рядом со списком при достаточной ширине, отдельно на телефоне или при большом шрифте.
- Главная получает реальные предстоящие и активные встречи. Это ограниченные страницы убывающего серверного timeline, без выдуманных общих счётчиков и обещания ближайшей встречи.
- Встречи: будущие/активные/история, фильтры «мои», «я организатор», «я участник», cursor pagination, обновление и сохранение загруженных строк при ошибке. Повторяющийся cursor останавливается; дубли ID объединяются с последней серверной проекцией.
- Создание обычной/запланированной встречи, ожидание ответа, изменение расписания, старт, завершение, отмена. Расписание меняется только у scheduled; управление жизненным циклом доступно владельцу. Завершение и отмена требуют подтверждения. Права и переходы проверяет backend.
- Вход по коду или HTTPS-ссылке текущего сервера, собственное членство/допуск, обновление состояния, выход. Invite URL разбирается локально: запрос никогда не следует на произвольный адрес. Запланированная регистрация admitted/left отображается отдельно от реального joined.
- История: организатор, фактическая длительность, разрешённые участники, признак сокращённого списка, сводка записей. Просмотр записей и чат не подменены заглушкой успешной операции.
- Календарь: месяц, выбор дня, месячная повестка, фильтры, все три вида timeline и отдельная дозагрузка каждой страницы. Время — `Instant`, отображение — выбранный IANA ZoneId. Включённая верхняя граница месяца задаётся минус 1 µs, согласно точности PostgreSQL. Неоднозначное время DST требует offset, несуществующее время отклоняется.
- Личный кабинет: сохранение displayName через PATCH, реальные данные аккаунта, информация о сервере/возможностях, тема, управление серверами и выход.

## Защита и ошибки

REST использует существующий auth context. Bearer не доступен UI, HTTPS проверяется обычным системным TLS/hostname verification; redirects и автоматические сетевые повторы выключены. Cookie передаётся только на auth-пути выбранного origin. После безопасного GET возможен один refresh с немедленным сохранением rotated cookie; изменение после 401 не отправляется повторно автоматически.

Данные и диалоги ограничены origin + account. Устаревшие загрузки отменяются, поздний ответ не возвращает прежние данные. Смена аккаунта, выход и истечение сессии очищают память; истечение переводит основной экран на вход. При удалении expired credentials независимо выполняются обе durable защиты: очистка ссылки профиля и удаление секретного файла.

Повторное нажатие мутации блокируется. При неизвестном результате создания сначала перечитывается серверный список; новое создание разрешается только после явной проверки пользователем. Серверные/HTML ошибки не показываются как raw body или пустой успешный список. 403/404/409/validation/API gap различаются. Ответ ограничен 128 KiB для auth и 512 KiB для встреч; проверяются UUID, размер/поля страниц и поддерживаемый диапазон времени. Данные встреч и черновики не записываются в Bundle или постоянный offline cache.

## Gaps и ограничения

- Аудио/видео и SFU WebRTC ещё не подключены. Вход/допуск подтверждают членство, а не медиасвязь. На этом этапе не запрашиваются камера/микрофон.
- Список и календарь обновляются по входу в раздел, после операций и вручную. Автоматический realtime refresh/уведомления и offline история не реализованы.
- Capabilities не предоставляет meetings/calendar/profile flags; отсутствие API отображается ошибкой, а не выдуманным флагом или fake success.
- Backend не предоставляет delete/rename/waiting-room edit существующей встречи, email/password/avatar update, отдельный dashboard/count/calendar endpoint. Для кабинета подтверждён только displayName.
- Действительное приглашение сразу подтверждает admission даже при waitingRoomEnabled; это фактическая политика backend. UI предупреждает об этом. Waiting/rejected/kicked отображаются, когда их возвращает сервер; Android moderation/admission действий организатора в этом этапе нет.
- История в календаре относится к завершению, затем к scheduledAt или createdAt — согласно backend. Неполная страница не выдаётся за полную повестку. Тема сохраняется; выбранный часовой пояс и календарный выбор остаются в памяти.
- Release APK собран без публикационной подписи. Проверки физических устройств, Android 8–15, нескольких реальных аккаунтов на production, аудио/видео и внешней сети VPS этим этапом не выполнялись.
