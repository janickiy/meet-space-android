# MeetSpace Android

Нативное приложение Kotlin + Jetpack Compose + Material 3. Этапы 02–04: авторизация, адаптивный каркас, SSH и установка Docker MeetSpace. Этап 05: главная, встречи, календарь и личный кабинет. Этап 06: нативные WebRTC-звонки, Pion/SFU и демонстрация экрана. Этап 07: личные и групповые чаты, папки, файлы и уведомления. Этап 08: записи, проигрыватель, настройки и APK/AAB. Этап 09: измерения памяти и ресурсов, исправления lifecycle/installer, безопасность и CI. Аудит backend и результаты этапов находятся в [docs/android](docs/android).

## 0.1.0 beta

Текущая версия — **0.1.0 beta**, `versionCode=16`: новая нумерация сохраняет возможность обновления предыдущего debug APK. Установочный файл: [MeetSpace-0.1.0-beta.apk](dist/MeetSpace-0.1.0-beta.apk).

Личный звонок запускается кнопкой телефона в заголовке личной переписки. Доступны входящий вызов, принятие/отклонение, микрофон, камера, экран, сворачивание в переписку и возврат; сервер сохраняет результат и длительность в истории чата. Вызов использует `/api/v1/calls` и отдельную комнату Pion; обычная встреча не создаётся клиентом. Принять звонок можно только на одном устройстве, переподключение проверяет владельца через REST. Запись и групповые звонки через личную переписку не предусмотрены.

На экране входа появилась регистрация: имя, email, пароль и подтверждение. После `/auth/register` выполняется обычный вход; если аккаунт создан, но вход не завершился, приложение предлагает войти без повторного создания аккаунта. Пароли не сохраняются. Экраны регистрации и личного звонка перенесены из обновлённого макета `meetspace-android-20261010` для телефона и планшета.

Входящие вызовы принимаются через действующую сессию приложения и UserWS/REST. Push для закрытого приложения пока не настроен. Сохраняется правило Android-клиента: при уходе приложения в фон микрофон и камера выключаются, после возврата включаются пользователем. Демонстрация экрана требует отдельного системного согласия. Физические устройства и системный входящий звонок поверх экрана блокировки требуют отдельной проверки.

Изолированный локальный стенд и команды интеграционных проверок: [testing/beta010](testing/beta010/README.md). Учётные записи и доверенный тестовый сертификат этого стенда существуют только в приватных тестовых файлах и не входят в APK.

Требуются JDK 17, Android SDK Platform 36, Build Tools 35.0.0 и Android Emulator для инструментальных проверок. Путь SDK задаётся локальным `local.properties` (`sdk.dir=...`) или `ANDROID_HOME`. Этот файл не входит в репозиторий. Gradle 8.13 скачивается проверяемым Wrapper; AGP 8.13.2 и Kotlin 2.2.21 зафиксированы в version catalog. minSdk 26, targetSdk 36.

## Модули

- `app`: Activity, ViewModel, маршруты первого запуска и три адаптивные вкладки (встречи, чаты, настройки аккаунта), Compose и интеграционные тесты.
- `core:model`: состояния сервера, аккаунта, встреч, сообщений, папок, уведомлений, возможностей и темы; без Android API.
- `core:data`: HTTPS API, timeline/жизненный цикл встреч/профиль, direct/group сообщения, вложения, папки, REST/WSS уведомления, нормализация origin, DataStore, Keystore, изолированные сессии и тесты с HTTPS MockWebServer.
- `core:media`: native libwebrtc M144, последовательная сигнализация, SDP/ICE/TURN, камера/микрофон/MediaProjection, аудиомаршруты и lifecycle.
- `core:designsystem`: синяя палитра, Inter, размеры и светлая/тёмная темы нового макета MeetSpace.
- `core:ssh`: JSch/crypto, отдельный DataStore публичных host keys, ограниченный read-only Linux probe, DNS/TLS диагностика, проверка подписанного installer bundle и управление заданием установки. С REST credentials не связан.

## Подключение

Введите корневой HTTPS URL без пути, userinfo, query и fragment. Приложение проверяет системное доверие TLS и `/version`, затем выполняет `/api/v1/auth/login`, `/auth/me` и `/capabilities`. Endpoint capabilities защищён, поэтому вызывается после входа. Cookie `meetrix_session` используется только на auth-путях точного origin. При перезапуске вход восстанавливается через `/auth/refresh`.

Access token хранится в памяти. Cookie зашифрован AES-GCM с ключом Android Keystore в приватной папке без backup. Пароль не записывается в настройки, saved state или логи. Каждый профиль сервера хранит один текущий аккаунт; при смене аккаунта прежний локальный секрет удаляется. Пользователь может добавлять/переключать/удалять профили. Выход пытается отозвать серверную сессию и удаляет локальную сессию; сбой сервера отображается явно.

Навигация: три нижние вкладки на телефоне и планшете; двухколоночные разделы от 780 dp (первый запуск — от 760 dp, подготовка звонка — от 840 dp). URL, email и выбранная вкладка переживают пересоздание Activity, пароль нужно ввести снова. Формы и содержимое прокручиваются при маленькой высоте/большом шрифте.

Проверено на ARM64 эмуляторе Android 16: 36 JVM тестов, 10 Compose тестов и два отдельных сценария реального входа/поворота/восстановления процесса/выхода. Сборка прошла; Lint: 0 ошибок, 23 предупреждения о новых версиях зависимостей. Полные результаты и скриншоты: [отчёт этапа 02](docs/android/02_FOUNDATION_REPORT.md).

## Реальная проверка входа

`LiveAuthTest` запускается только при наличии `files/live-auth.properties` в приватной папке тестируемого приложения. Обычный suite его исключает. Файл содержит `server`, `email`, `password`; передавать эти данные через source code, Gradle properties или аргументы runner не нужно. Перед тестом очистите данные тестового экземпляра приложения, затем передайте файл через `adb exec-in run-as com.meetspace.app`. Файл удалить после проверки. Такой сценарий предназначен для выделенной тестовой учётной записи и debug APK.

Два метода запускаются раздельно: `connectLoginAndRotate`, затем остановка процесса приложения, затем `restoreAfterProcessRestartAndLogout`. Это проверяет реальное восстановление из Keystore/DataStore, а не только сохранение ViewModel. Проверка вызывает login/refresh/logout; встречи и данные аккаунта не создаются и не редактируются.

## Встречи и личный кабинет

В текущей версии 0.7.0 пять разделов: главная, чаты, встречи, календарь, профиль. Главная получает предстоящие и активные встречи. Список поддерживает будущие/активные/историю, собственные/участвующие встречи и серверную cursor pagination. На широком окне список и детали видны рядом; на узком окно деталей открывается отдельно. Только организатор видит управление жизненным циклом; окончательное решение принимает сервер.

Создание и планирование используют реальные REST-операции. Повторное нажатие во время запроса блокируется. При неизвестном результате создания приложение обновляет данные и требует явной проверки списка перед новым созданием. После истечения access token безопасный GET может один раз обновить сеанс; мутация автоматически не повторяется.

Календарь объединяет три серверных timeline за месяц в выбранном IANA-часовом поясе. Сервер относит завершённые встречи к дате завершения, остальные — к расписанию либо созданию. Недозагруженные страницы отмечаются и доступны отдельной кнопкой. При планировании неоднозначное время перевода часов требует UTC offset, несуществующее время отклоняется. Время хранится как Instant; выбранный пояс и данные встреч остаются в памяти. Профиль редактирует только displayName; тема и управление профилями серверов доступны как раньше.

Контракт и ограничения: [05_API_CONTRACT.md](docs/android/05_API_CONTRACT.md). Порядок проверок: [05_MEETINGS_TESTING.md](docs/android/05_MEETINGS_TESTING.md). Данные встреч не сохраняются в offline cache и очищаются при смене сервера/аккаунта или завершении сеанса.

## SSH-мастер

На первом экране выберите «Развернуть свой сервер». Введите hostname/IP, SSH-порт, пользователя SSH и будущий HTTPS-домен. Новый публичный ключ подтвердите только после сравнения SHA-256 отпечатка с независимым источником (панель VPS/администратор). Приложение запоминает публичный ключ для точного host+port; смена ключа блокирует передачу credentials. Сброс доверия — отдельное подтверждённое действие, после которого сравнение выполняется заново.

После проверки ключа выберите пароль SSH или private key через системный выбор файла. Поддерживаются OpenSSH v1 (включая encrypted bcrypt 1–64 rounds) и незашифрованные традиционные RSA/EC PEM; RSA 2048–8192, ECDSA P-256/P-384/P-521 и Ed25519. PKCS8, encrypted traditional PEM, PuTTY/PPK и hardware/agent keys пока не поддерживаются. Максимум файла 256 КиБ. Passphrase используется только для локальной расшифровки. Пароль/ключ не сохраняются, SAF URI permission не закрепляется; после операции/отмены буферы очищаются. Текстовые поля пароля/passphrase не сохраняются при пересоздании Activity.

Требуется сервер с современными алгоритмами и SSH strict KEX (например, актуальный patched OpenSSH). Не поддерживаются keyboard-interactive/MFA и обход host-key verification. Проверка имеет общий timeout 45 секунд, подключение — 15 секунд. Отмена закрывает клиентский socket/channel/session; read-only probe не устанавливает пакеты, не меняет firewall/Docker и не запускает установку. Sudo проверяется только через `sudo -n true`.

Результат содержит PASS/WARN/BLOCKED/UNKNOWN для платформы, ресурсов, прав, Docker/Compose, портов, DNS/TLS, известных путей установки и firewall. Ресурсные пороги предварительные; внешние cloud firewall/NAT и ACME challenge не подтверждаются этим probe. Установка открывается отдельной кнопкой и требует просмотра плана и подтверждения. Как повторить реальные тесты в disposable VM: [03_SSH_TESTING.md](docs/android/03_SSH_TESTING.md).

Этап 03 проверен: 91 JVM-тест, 16 Compose-тестов, 7 реальных SSH-сценариев на отдельной Ubuntu VM и полный UI-путь к результатам preflight. Неизвестный/изменённый host key блокирует auth, что отдельно подтверждено серверным auth log. Debug и unsigned minified release собираются; Lint без ошибок. Скриншоты, ограничения и результаты: [03_SSH_PREFLIGHT_REPORT.md](docs/android/03_SSH_PREFLIGHT_REPORT.md).

## Автоматическая установка Docker MeetSpace

После SSH preflight выберите «Подготовить план установки». Укажите домен, публичный IPv4 и ACME email, повторно предоставьте SSH-доступ. Первая версия поддерживает новый выделенный Ubuntu 24.04 / systemd / Python 3, root или passwordless sudo, amd64/arm64, 4 CPU, 8 ГиБ RAM и 30 ГиБ свободного диска. Домен должен указывать напрямую на IPv4 VPS; DNS, ресурсы, занятые порты и существующие установки проверяются до изменений.

Просмотрите commit/версию, порты, каталог, действия и ограничения. Запуск требует подтверждения плана, согласия с условиями Let's Encrypt и отдельного разрешения установить Docker/Compose, если их нет. Установщик собирает backend на VPS из закреплённого commit и проверенных base images, создаёт секреты только на сервере, делает backup перед миграциями и проверяет HTTPS/WSS/TURN. Внешние БД/Redis/RabbitMQ/S3 порты не публикуются.

Задание выполняется через systemd независимо от SSH. «Закрыть наблюдение» очищает доступ из памяти клиента и сохраняет публичный ticket. Для остановки используйте отдельную кнопку; остановка ждёт безопасной границы команды. «Восстановить наблюдение» сначала запрашивает состояние, затем позволяет явно продолжить. После потери ответа повторного автоматического apply нет. Можно вести одно сохранённое задание; завершённое убирается с устройства отдельной кнопкой. Пользовательские данные на VPS при отмене/ошибке не удаляются.

## Звонки

В активной встрече нажмите «Подключиться к звонку». На экране перед входом можно отдельно разрешить и включить камеру/микрофон или войти только для прослушивания. После подтверждения допуска приложение подключается к Pion SFU через защищённую сигнализацию. Для экрана Android каждый раз запрашивает системное разрешение. Показ останавливается кнопкой в звонке, уведомлении или системном индикаторе.

При уходе в фон камера и микрофон отключаются; их можно включить после возврата. Экран продолжает передаваться через foreground service. При потере сети создаётся новое соединение, устройства остаются выключенными; показ экрана требует нового разрешения. Перед истечением временных TURN credentials выполняется такое же переподключение. Системный звук экрана, PiP, чат и управление записями не входят в этап 06.

Время и индикатор записи берутся из данных встречи, презентация из макета включена только в тесты скриншотов.

## Чаты, папки, файлы и уведомления

Личные диалоги и группы работают через реальный REST API и глобальный пользовательский WSS. Доступны поиск чатов/пользователей, ответы, правка/удаление собственных сообщений, read/unread, presence, управление группой и личные папки с чатами и встречами. На широком окне список и переписка расположены рядом; на узком или при большом шрифте открываются по очереди.

Вложения выбираются и сохраняются через системный диалог Android, без разрешения на весь накопитель. Поддерживаются JPG/PNG/WebP/PDF/TXT/CSV: до пяти файлов по 10 MiB, с проверкой размера и SHA-256. Повтор отправки после неопределённого сетевого результата использует исходный clientRequestId и неизменный текст/список вложений.

Загруженная история хранится только в RAM с ограничениями: до десяти чатов и окна из двухсот сообщений на чат. Более старые страницы можно читать дальше: окно сдвигается, не увеличивая объём кэша. Она доступна при временной потере сети, но очищается при выходе, смене аккаунта/сервера или завершении процесса. После восстановления WSS приложение сверяет состояние с REST. Автоматической отправки очереди offline-сообщений нет.

Центр уведомлений и календарные события работают без Firebase. Системные уведомления активного приложения требуют разрешения Android и не показывают текст сообщений на экране блокировки. Фоновые push ещё не настроены: сборка не содержит google-services.json, реальные FCM и gateway не проверялись. Порядок подключения: [07_FCM_SETUP.md](docs/android/07_FCM_SETUP.md).

Контракт: [07_API_CONTRACT.md](docs/android/07_API_CONTRACT.md). Проверки: [07_MESSAGING_TESTING.md](docs/android/07_MESSAGING_TESTING.md). Итоги и ограничения: [07_MESSAGING_REPORT.md](docs/android/07_MESSAGING_REPORT.md).

## Этап 08: записи, материалы и релиз

Версия приложения 0.8.0 (7). Во «Встречах» и истории доступны записи: нативный проигрыватель Media3, перемотка, сохранение через системный выбор папки с проверкой размера/SHA-256. Расшифровки загружаются страницами; готовые материалы доступны и после отключения сервиса их генерации. В профиле — уведомления, тема, системные разрешения и сведения о данных.

Видео передаётся потоково, без сохранения временных ссылок в UI/на диск. Смена аккаунта закрывает активные потоки. Глобального API записей нет, поэтому сначала выбирается встреча. Firebase/push-шлюз пока не настроены.

[План](docs/android/08_RECORDINGS_PLAN.md), [контракт](docs/android/08_API_CONTRACT.md), [проверки](docs/android/08_TESTING.md), [итоговый отчёт](docs/android/08_RECORDINGS_REPORT.md), [подпись и выпуск](docs/android/08_RELEASE.md), [данные и разрешения](docs/android/08_PRIVACY.md).
